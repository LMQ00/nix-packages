# Repository Guidelines

## Project Overview

Personal Nix package collection managed as a single-input Flake. It exposes **14** packaged applications/libraries through both a reusable overlay and `packages.<system>` outputs; `musicdl` is the default package. This repo packages third-party software — no application code is authored here.

## Architecture & Data Flow

```text
flake.lock → nixpkgs-unstable (single input, pinned revision)
flake.nix → pkgsForSystem: import nixpkgs { allowUnfree; permittedInsecurePackages=["libsoup-2.74.3"]; overlays=[self.overlays.default]; }
          → overlays.default: callPackage ./pkgs/<name> for all 14 packages
          → packages.<system>: re-exports the same 14 as pkgs.<name>; default = pkgs.musicdl
          → devShells.<system>.default: nixpkgs-fmt + nil
nix build/run → evaluated derivation → Nix store output / wrapped executable
```

- `flake.nix` is the source of truth: every package is registered **twice** — once in `overlays.default`, again in `packages.<system>`. Keep both lists synchronized; add/remove packages in both places.
- Package families, all in `pkgs/<name>/default.nix`:
  - **Python** (musicdl, construct, pymp4, pywidevine): `buildPythonApplication`/`buildPythonPackage` + `pyproject`, `fetchPypi`/`fetchFromGitHub`.
  - **Node/pnpm** (sub-store): `pnpm.configHook` + `pnpm.fetchDeps`, `makeWrapper` over `nodejs`.
  - **Prebuilt desktop**: `.deb` + `autoPatchelfHook` (qq, aurevoy, hanako), AppImage (wechat, astudio-linux), Wine prefix (wecom-wine), `buildFHSEnv` (sunlogin), Docker-container wrapper (baidunetdisk), release binary + dynamic-linker wrapper (omp).
- The flake targets 4 systems (x86_64-linux, aarch64-linux, x86_64-darwin, aarch64-darwin), but only `omp` and `astudio` build outside x86_64-linux; other packages declare `meta.platforms` accordingly.

## Key Directories

- `pkgs/<package>/default.nix` — one self-contained derivation per package; no other files inside package dirs.
- `flake.nix` — inputs, supported systems, overlay, package exports, devShell, unfree/insecure config.
- `flake.lock` — pinned nixpkgs revision; generated by Nix, **never hand-edited** (see FLAKE_LOCK.md).
- `README.md` — public package table, install examples, license list; keep in sync with package changes.
- `FLAKE_LOCK.md` — lockfile maintenance instructions.
- There is no `src/`, `tests/`, `scripts/`, or `.github/`. Root `result`/`result-1` are gitignored build-output symlinks (a broken `result-1` is normal); `omp-darwin-*`/`omp-linux-arm64` are stray manual downloads that are **not** gitignored (delete or ignore them); `.pi-subagents/` is harness scratch.

## Development Commands

Run from the repository root:

```bash
# Enter a shell containing nixpkgs-fmt and nil
nix develop

# Build one package; canonical command when unfree evaluation is required
NIXPKGS_ALLOW_UNFREE=1 nix build .#<package> --impure

# Run / smoke-test a package
nix run .#<package> --impure

# Update the locked nixpkgs input / every input
nix flake update nixpkgs
nix flake update

# Regenerate the lockfile when required
nix flake lock

# Format Nix files (inside nix develop)
nixpkgs-fmt pkgs/musicdl/default.nix flake.nix
```

- Do **not** rely on `nix fmt` — `flake.nix` has no `formatter.<system>` output.
- Source-update flow: set the package `hash` to `lib.fakeHash`, build the package, then replace it with Nix's reported hash. Never bypass fixed-output hash verification.

## Code Conventions & Common Patterns

- Keep package names and directories aligned: `pkgs/foo/default.nix` is exported as `foo`.
- Use an argument set and request only dependencies the derivation uses; order `lib` first, then `stdenv`/`stdenvNoCC`, fetchers, build hooks, runtime libs. Prefer standard fetchers (`fetchurl`, `fetchFromGitHub`, `fetchPypi`) with fixed SRI hashes (`sha256-...`; the `sha256:` colon form in astudio and bare hex in baidunetdisk are legacy).
- Define `pname` and `version` near the top. Binary packages use `finalAttrs` (qq, aurevoy, sub-store) or `let`-bound values with `inherit` (omp, astudio, wechat, baidunetdisk); Python packages use `rec`.
- Separate `nativeBuildInputs` (hooks, dpkg, makeWrapper, pnpm) from `buildInputs` (runtime libraries). Prefer standard hooks (`autoPatchelfHook`, `makeWrapper`, `wrapProgram`, `appimageTools`, `pnpm.configHook`) over ad-hoc environment mutation.
- **Wrappers are the established boundary** for runtime-only dependencies, PATH/RPATH fixes, and per-user state (e.g. Wine prefix copy). Keep wrapper behavior explicit and minimal. Distinct wrapper idioms in use:
  - `makeWrapper` over the app binary — aurevoy renames `desktop` → `.aurevoy-wrapped` and sets `GST_PLUGIN_SYSTEM_PATH_1_0`; sub-store wraps `nodejs` with the bundle as `--add-flags`.
  - `makeWrapper` over the **dynamic linker** — omp (`makeWrapper "$(cat ${dynamicLinker})" ...`). Never `patchelf` omp's binary: it corrupts embedded bunfs data (explicit comment in the file).
  - `makeShellWrapper` with `--prefix`/`--set`/`--run` — qq (XDG_DATA_DIRS, LD_PRELOAD, ozone flags; disables auto-update by writing a read-only `versions/config.json`).
  - `wrapProgram` in `postFixup` — musicdl (`--prefix PATH : ${lib.makeBinPath [ ffmpeg nodejs ]}`).
  - `appimageTools.wrapAppImage`/`wrapType2` — wechat, astudio (Linux AppImages need FUSE: `programs.fuse.enable`).
  - `writeShellScript` + `substituteInPlace` placeholders — baidunetdisk (`@DEB@`), wecom-wine (`@WINEPREFIX_TEMPLATE@`), hanako outer layer (`@out@`).
  - `buildFHSEnv` — sunlogin only; it is the sanctioned exception, **not a general pattern**. baidunetdisk's Docker-container wrapper is a unique case (patchelf SIGTRAPs on its Electron stack).
- Use `lib.makeLibraryPath`/`lib.makeBinPath` for LD_LIBRARY_PATH/PATH; `map lib.getLib` for `runtimeDependencies`.
- `doCheck = false` is the norm (5 of 14) because upstream tests are unsuitable for the Nix sandbox; give a concrete reason when adding it (e.g. sub-store: tests need network). Bare `# 禁用测试` comments are discouraged; no package enables checks.
- Every binary package sets `meta.sourceProvenance = with sourceTypes; [ binaryNativeCode ];` (missing in wecom-wine and sunlogin — add it). Meta blocks include description, homepage, license, `mainProgram` (apps), `platforms`, and `maintainers`.
- Rationale comments are bilingual (Chinese why-comments, English meta strings) — preserve this style and keep the "why" when copying a pattern.
- No package has `passthru.updateScript`; don't introduce one.

## Important Files

- `flake.nix` — source of truth for systems, overlay/packages registration, and unfree/insecure config.
- `pkgs/musicdl/default.nix` — default package; representative Python app plus `wrapProgram` wrapper.
- `pkgs/sub-store/default.nix` — representative Node/pnpm package (`pnpm.fetchDeps`, fetcherVersion 4).
- `pkgs/sunlogin/default.nix` — most complex: FHS exception, manual `patchelf` loop, real-dir copy to defeat the daemon client check; flake passes `gconf = final.gnome2.GConf`.
- `pkgs/wecom-wine/default.nix` — Wine prefix template and first-run copy behavior.
- `pkgs/astudio/default.nix` — platform-conditional AppImage/macOS bundle.
- `pkgs/omp/default.nix` — multi-platform release binary with dynamic-linker wrapper.
- `pkgs/baidunetdisk/default.nix` — newest package; Docker-container wrapper.
- `README.md`, `FLAKE_LOCK.md` — public docs; FLAKE_LOCK.md covers lockfile maintenance.

## Runtime/Tooling Preferences

- Use **Nix Flakes** with the repository's pinned `nixpkgs-unstable`; Nix is the package manager and build runtime.
- `nix develop` provides only `nixpkgs-fmt` and the `nil` Nix language server. No Node, Python, pnpm, or other host-language runtime is a repository prerequisite; derivations supply what they need.
- Unfree packages are supported through the flake configuration. Use the canonical `NIXPKGS_ALLOW_UNFREE=1 ... --impure` command when required by the target package or caller configuration.
- `libsoup-2.74.3` is deliberately permitted as insecure for `sunlogin`; do not broaden that exception.
- Do not edit `flake.lock` manually. Regenerate it with Nix (`nix flake lock` / `nix flake update`) and commit the result.
- Provide commit messages for the user to commit rather than creating commits automatically.

## Testing & QA

- No test suite, `checks` output, CI workflow, linter, coverage tool, or pre-commit configuration exists; `nix flake check` has nothing to run.
- The focused verification for a derivation change is a successful build of that package:

  ```bash
  NIXPKGS_ALLOW_UNFREE=1 nix build .#<package> --impure
  ```

- For changes affecting startup or wrappers, also smoke-test the intended executable with `nix run .#<package> --impure` when safe and practical.
- After test builds, clean temporary/unreferenced Nix build outputs: `nix-store --gc`.

## Change Checklist

1. Update `pkgs/<package>/default.nix` and verify its focused build.
2. Add or update the package in **both** the overlay and `packages` export lists in `flake.nix`.
3. Update `README.md` package table and license information; update NixOS configuration only when that package is installed there.
4. Format touched Nix files with `nixpkgs-fmt`, clean after test builds, and provide a commit message rather than creating a commit automatically.
